# SC2008-LAB04 流量分析笔记

## 记录类型和统计单位

采样日志中的 `FLOW` 记录用于本次报文分析，`CNTR` 记录是计数器信息，应分别处理。这里按记录累计得到的是采样包数；连接数和字节数需要另外定义统计方式。

读取 CSV 时先检查列数，再将协议号、端口和 IP packet size 转成整数。练习文件末尾多出的空列可以在确认其为空后移除。缺失地址 `-` 不应成为一个参与排名的主机。

IP 相关分析还需按 EtherType 筛选 IPv4 和 IPv6。ARP 等非 IP 记录不能计入 IP 协议占比或 IP 字节总量。

## 主机和通信对

源地址计数给出 top talkers，目的地址计数给出 top listeners。Python 的 `Counter` 适合累加这些离散键，并用 `most_common` 获取排名。

通信对采用有序组合 `(source IP, destination IP)`。A 到 B 与 B 到 A 分开计数，便于观察流量方向。若要研究双向主机对，需要先统一两个端点的顺序，并在结果中说明这一口径。

地址注册机构可通过 RDAP 查询。注册信息描述地址段的持有者；具体设备、实际用户和通信目的还需要其他证据。

## 协议占比和端口

TCP 的 IP protocol number 为 6，UDP 为 17。以全部有效 IP 记录为分母时，TCP 和 UDP 的比例之和可能小于 100%，剩余部分属于其他 IP 协议。

$$
\text{协议占比}=\frac{\text{该协议的采样包数}}{\text{有效 IP 采样包数}}\times 100\%.
$$

目的端口统计只用于 TCP/UDP 记录。如果将两者按同一个端口号合并，应注明统计口径。服务查询则应区分传输协议，因为 TCP 和 UDP 具有各自的端口注册项。

端口注册名称可用于说明常见服务。确认某个包实际属于该应用，还需要结合报文内容或协议解析；动态与私有端口也不应硬套一个应用名称。

## 采样流量的单位

设每个包被采中的概率为 `1 / s`，样本中各 IP packet size 的和为 `B` bytes。在这一采样假设下，总 IP 字节量估计为 `sB`。

$$
\widehat{V}_{\mathrm{MB}}=\frac{sB}{10^6}.
$$

本次采用十进制 MB，即 `1 MB = 1,000,000 bytes`。以 `2^20` bytes 为单位时应写 MiB。计算 IP 流量时累加 IP packet size；Ethernet frame size 对应另一个统计范围。

如果题目要求长度为 `T` 秒的监测窗口中的总流量，计算至此即可。只有计算平均速率时才除以时间：

$$
\widehat{R}_{\mathrm{Mbps}}=\frac{8sB}{T\times 10^6}.
$$

只有当采样率一致时，才能先求和再统一乘以同一个 `s`。逐条采样率不同时，需要按各记录对应的采样权重计算。

## 图表和复现检查

前五名的离散排名适合横向条形图。按包数降序排列，数值轴从零开始；地址较长时可让图中编号与相邻表格对应。图注需写清是包数、字节数还是比例。

本次用 SciencePlots 统一字体与线条，并保留灰度配色。图表样式独立于统计函数，更换样式后可直接比较数值输出是否一致。

复查时重点核对以下几项：

- 使用的是正式数据还是练习数据。
- 协议计数之和是否等于对应的 IP 记录总数。
- 排名表、图表与程序输出是否来自同一次统计口径。
- 流量是否已经按采样率放大，单位和时间窗口是否明确。
- 粘贴代码到提交文本框后，Python 缩进和文件末尾是否完整。
