## 1. 内核信号量：维护非负的可用许可数

本实验的 `value` 表示 available permits（可用许可数）：

- `sem_wait`：先取得该信号量的锁；值为 0 就睡眠并在醒来后重新检查；大于 0 才减一。
- `sem_signal`：在锁内加一，随后唤醒该信号量通道上的等待者，再释放锁。
- `sem_getvalue`：在锁内读取快照，不改变计数。

这里的计数在正常使用中不为负；不要直接套用 lecture 中“先减一，负数表示等待者数量”的另一种实现。等待者由 xv6 的进程状态与 channel 记录，不编码在 `value` 的负数部分。

`sem->value` 是通过指针访问结构体成员，等价于 `(*sem).value`；`&sem->lock` 则取成员锁的地址。传给 `sleep()` 的 `sem` 本身已是对象地址。作为独立语句，`sem->value--` 与 `sem->value -= 1` 的减一效果相同；两者都不会凭语法自动获得并发原子性，仍需锁保护。

系统启动时的 `seminit()` 初始化信号量表与锁；用户程序的 `sem_init(value)` 经系统调用分配一个表项，返回整数 ID，两者不是同一层接口。课程骨架提供 32 个表项及系统调用接线。

生命周期约定是先分配、再共享使用、全部使用者结束后才释放。`sem_free()` 仅把表项标为可再分配，不负责清理睡眠者。本实验不支持使用期间并发 free/reuse，也未补充负初值校验或 FIFO 公平性；它是课程指定场景下的实现，不是通用生产级同步库。

## 2. 共享计数器：保护完整 Read–Modify–Write

课程提供的 `ucnt_get(0)` 和 `ucnt_set(0, value)` 访问共享内核计数器。两个进程各加一 1000 次，期望最终值为 2000。

未保护时，两个进程可能都读到同一个旧值，各计算一次加一，再先后写回相同的新值；两次操作只留下一个增量。课堂一次运行得到 1935，体现 lost update（丢失更新），但具体数值取决于调度。

正确的临界区必须把读取和写回包在一起：

```text
wait(mutex) → get old value → calculate old + 1 → set new value → signal(mutex)
```

仅分别保护 `get` 和 `set` 仍会在两次调用之间发生交错。信号量必须在 `fork()` 前初始化为 1；之后父子进程持有相同 ID，指向同一个内核信号量，而不是各自创建一把锁。

父进程完成自己的循环后 `wait()` 子进程结束，再读最终值、断言等于 2000，并释放信号量。最终课堂综合运行通过此断言。

## 3. Bounded Buffer：三个信号量分工

内核 `ubuf` 是容量 16 的环形缓冲区，读操作推进 `head`，写操作推进 `tail`。提供的读写函数在数据访问与索引更新之间主动 `yield()`，使并发冲突更容易发生；不能删掉这些 `yield()` 来让测试看起来通过。

| 信号量 | 初值 | 等待成功后取得的资格 |
| --- | --- | --- |
| `empty` | `UBUF_SIZE = 16` | 可写入一个空槽 |
| `full` | 0 | 可读出一个已有元素 |
| `mutex` | 1 | 可独占访问缓冲区及其索引 |

三个 ID 均在创建生产者之前初始化。生产者与消费者的执行顺序如下：

| 阶段 | Producer（生产者） | Consumer（消费者） |
| --- | --- | --- |
| 等待资源 | `wait(empty)` | `wait(full)` |
| 进入临界区 | `wait(mutex)` | `wait(mutex)` |
| 完整读写调用 | `ubuf_write(character)` | `ubuf_read()` |
| 退出临界区 | `signal(mutex)` | `signal(mutex)` |
| 发布新资源 | `signal(full)` | `signal(empty)` |

先等待空槽或数据，再取得互斥权。如果缓冲区已满，生产者却持着 `mutex` 等待 `empty`，消费者就无法进入临界区取走元素，双方会死锁；空缓冲区上消费者的反向错误同理。

`empty/full` 负责计数与操作顺序，不能代替 `mutex` 对完整缓冲区操作的互斥。信号量许可可以跨越 `ubuf` 内部的 `yield()` 持有，因为 `sem_wait()` 返回前已释放其内部 spinlock；持有一个许可并不等于一直持着内核自旋锁。

无操作在途时，空槽数与已有元素数之和是 16；若某进程已领取许可而尚未发布另一种许可，中间瞬间的 `empty + full` 可以小于 16，不能把每次读取这两个值的和都断言为 16。

## 4. 工作量、结果与测试边界

测试中两个子进程各发送 48 个字符，不发送字符串结束符；父进程消费 96 个字符，然后等待两个子进程退出，最后释放三个信号量。课堂最终输出包含缓冲区 PASS 和总入口的 `ALL TESTS PASSED`。

需要区分三种结论：

- `sem_basic` 的 1 → 0 → 1 检查说明基本计数接口符合该测试，不涉及在 0 上执行第二次 wait。
- 计数器得到 2000 说明这次完整运行未出现可见的计数丢失；正确性还依赖上述临界区设计，而非单次数字。
- 缓冲区断言只检查字符属于原消息的合法字符集合，并未核对完整消息序列、每个字符的频次或来源。因此 PASS 不等于穷尽所有并发情形的证明。

此次没有新增压力测试、执行完整 `usertests` 或测量同步开销；不要把这些写成已完成的实验结果。

## 5. 复测时的排错顺序

1. 先检查初值和初始化位置：计数器锁为 1；缓冲区是 16、0、1；所有共享 ID 在 `fork()` 前创建。
2. 核对 `wait/signal` 配对，以及是否覆盖完整读改写和整个 `ubuf` 调用；不要关闭已有断言。
3. 核对 kernel 中先持锁、`while` 等待、计数更新、唤醒及解锁的顺序。
4. 如果断言导致提前退出或程序挂起，先退出并重新启动 QEMU；失败路径可能留下表项、子进程或缓冲区状态，不能把后续污染当成新修改的结果。

## 一分钟回顾

原子 test-and-set 解决多个 CPU 同时抢锁；`sleep/wakeup` 用条件锁与进程锁的交接避免丢失唤醒。信号量把“资源是否可用”转化为许可计数；互斥必须保护完整逻辑操作。计数器使用一个初值为 1 的信号量，有界缓冲区使用 `empty/full/mutex`，并且先等待资源、再取得互斥权。
