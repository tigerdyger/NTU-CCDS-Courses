## 任务概述

沿着虚拟地址、页表项和物理页的关系，先观察立即分配，再将正数 `sbrk()` 改为只扩展地址范围，由首次合法读写触发实际分配；同时保留非法访问保护，并让退出和缩堆能够处理尚未映射的页。

## 完成与验证

| 任务 | 课堂截图中的结果 |
| --- | --- |
| 立即分配基线 | 初始 `VP=4, PP=4`；`sbrk(122880)` 后 `VP=34, PP=34`；触碰 30 页后仍为 `PP=34` |
| 非法读写 | `fault read`、`fault write` 访问 `0x4000`，分别报告 cause 13、15；进程终止并返回 shell |
| 惰性分配 | 初始 `VP=4, PP=4`；预留 30 页后 `VP=34, PP=4`；逐页触碰后 `PP=34` |
| 部分触碰与退出 | 临时版本预留 30 页、仅触碰 1 页，`PP=4 → 5`；退出未出现 panic |
| 缩堆 | 临时版本收回预留范围后回到 `VP=4, PP=4`；最终恢复完整触碰 30 页的 `lazytest.c` |

这些结果来自 `sys_countpp` 返回类型修正前的课堂截图。归档版将其由 `uint` 改为 `uint64`，与系统调用声明及调度表一致；该修改后的 Linux/QEMU 运行仍待复测。本机没有 QEMU 或 RISC-V GCC；本地检查方法与结果见 [代码复现说明](code/README.md)。

`lazytest` 的成功提示只检查触碰后增量至少为 30，部分错误路径仍以状态 0 退出，因此须核对原始 VP/PP 数值和错误输出。上述检查未覆盖带未映射空洞的 `fork()`、内核 `copyin/copyout` 对未触碰页的访问，也未实现交换、页面置换或自动栈增长。
