## 1. 页表与计数：地址范围不等于实际映射

虚拟地址经多级页表找到叶 PTE（页表项），叶项记录物理页和访问权限。`PTE_V` 表示条目有效；`R/W/X` 表示读、写、执行权限，`PTE_U` 控制用户态访问。有效条目仍可能因权限不足而触发异常。

Sv39 的页面为 4096 bytes，每项 PTE 为 8 bytes，因此一张页表有 `4096 / 8 = 512 = 2^9` 项。地址分解如下，位号从 0 开始：

| 字段 | 位范围 | 用途 |
| --- | --- | --- |
| VPN[2] | 38–30 | 根页表索引 |
| VPN[1] | 29–21 | 中间页表索引 |
| VPN[0] | 20–12 | 叶页表索引 |
| Offset | 11–0 | 页内字节偏移 |

xv6 只使用 `MAXVA` 以下的地址；在该范围内高位为零。`walk()` 返回叶 PTE 的地址，`alloc=1` 时可以补建中间页表，但不会自动分配堆数据页；`walkaddr()` 返回用户映射对应的物理页基址，并检查 `PTE_U`。因此不能直接用 `walkaddr()` 统计包含保护页的 PP。

`countvp()` 按 `PGROUNDUP(p->sz) / PGSIZE` 统计地址范围覆盖的页数。`countpp()` 在 `[0, p->sz)` 内逐页检查有效且带 `R/W/X` 的叶映射；此口径包含 guard page（保护页），不包含页表自身占用的物理页，也不是全系统空闲页或唯一物理页框计数。`walk(..., 0)` 不分配页表，避免观察动作改变被统计对象。

本次本地将 `sys_countpp()` 的返回类型从 `uint` 改为 `uint64`，使定义与 `syscall.c` 的声明和系统调用表一致。课堂的小页数输出不能检验 C 函数接口类型是否一致；修正后的检查记录见代码说明。

## 2. 预留与首次触碰：分开更新范围和分配物理页

原始立即分配路径是 `morecore → sbrk → sys_sbrk → growproc → uvmalloc`；`uvmalloc()` 为新增页面调用 `kalloc()`、清零，再通过 `mappages(pagetable, va, size, pa, perm)` 建立映射。正数 `sbrk()` 扩堆，零参数查询当前 break，负数缩堆；成功均返回修改前的 break。

正数 `sbrk(n)` 保存旧 break，检查加法溢出和 `TRAPFRAME` 上界，只更新 `p->sz`，随后返回旧 break。因此预留 `30 × 4096 = 122880` bytes 后 VP 增加 30，PP 暂不增加。

用户读写未映射页时，`scause=13/15` 分别表示 load/store page fault，`stval` 给出被访问的地址，`sepc` 给出故障指令的地址；取指缺页的 cause 为 12。本实验只对合法堆读写补页。

异常入口经过 `trampoline.S` 的 `uservec`，保存用户状态并切换页表，再进入 `usertrap()`。trampoline 在用户、内核页表中映射到同一虚拟地址，使切换页表时其指令仍可执行；返回由 `usertrapret()` 和 `userret` 配合完成，缺页判定和分配在 `usertrap()` 中。处理流程为：

1. 先以原始地址检查 `heap_start <= addr < p->sz` 且 `addr < TRAPFRAME`，再用 `PGROUNDDOWN` 定位页。先向下取整可能掩盖非页对齐 break 之后的越界访问。
2. 用 `walk(..., 0)` 检查 PTE；若已经有效，终止进程，保留原有权限保护，不能把权限错误当作待分配页重新映射。
3. 对合法空洞执行 `kalloc()`、整页清零，再建立 `R/W/U` 映射。分配失败则终止进程；映射失败先 `kfree()` 回收刚分配的数据页，再终止。
4. 成功返回时保留故障指令的 `epc`，让 CPU 重试原读写；只有系统调用的 `ecall` 路径才按该实现执行 `epc += 4`。

`heap_start` 是本实现选择的惰性堆下界，在 `exec()` 完成映像与栈布局后设为当时的 `sz`，并随进程初始化和复制维护。它限制允许补页的范围，避免把原有映像或栈保护区的错误访问补成可写页；这项设计没有实现栈增长。

`fault` 只调用 `sbrk(0)`，再以 `PGROUNDUP(break)` 选择第一个未分配页，未曾预留目标地址；所以惰性分配后仍应终止。它用 `volatile` 保留真正的读写，不能把打印目标地址本身当成已发生访存。

## 3. 退出和缩堆：允许地址范围中存在空洞

惰性分配后，`p->sz` 内会出现尚无 PTE 或 PTE 无效的页。`uvmunmap()` 遇到这些空洞直接跳过；对于已映射页，按 `do_free` 释放物理页并清除 PTE，仍保留非叶条目等结构错误的检查。这样只触碰一页的进程退出时，不会因其余 29 页从未分配而 panic。

负数 `sbrk()` 检查缩减量不能越过 `heap_start`，再调用 `uvmdealloc()` 回收完整页并更新 `sz`。部分页的保留遵循页粒度回收规则；课堂缩堆截图验证的是回到原始 `VP=4, PP=4` 的整页情形。

## 4. 证据与尚未覆盖的路径

课堂完整触碰的关键变化是 `VP/PP: 4/4 → 34/4 → 34/34`；只触碰一页时 PP 为 5。判断实验结果应核对这些数值以及错误输出，因为现有 `lazytest` 使用“增量至少 30”的条件，且打印部分错误后仍会 `exit(0)`。

`uvmunmap()` 允许空洞不意味着所有内存路径都已支持空洞：归档实现没有补齐惰性 `fork()`，也没有为 `copyin/copyout` 访问未触碰页增加按需分配。交换、页面置换和可选栈增长均不在已实现范围内；现有截图不能覆盖这些路径。

## 一分钟回顾

VP 记录地址范围，PP 记录本实验口径下的有效叶映射。惰性分配把“预留地址”与“首次触碰时分配清零物理页”分开；补页前检查原始地址和权限，补页后重试同一条指令。回收必须容忍合法空洞，完整支持仍需逐条检查复制与内核访存路径。
